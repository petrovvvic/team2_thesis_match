# 07: Komplexitätsreduktion im Professoren-Profil

## Meta

Status
: Work in progress - **Decided** - Obsolete

Updated
: 23-Jun-2026

## Problem Statement

Im Professoren-Profil (Screen 7) muss der Betreuungsstatus verwaltet werden. Studierende müssen erkennen, ob ein Professor aktuell Kapazitäten für neue Bachelorarbeiten hat.

Der initiale Ansatz sah ein kombiniertes Dropdown-Feld vor, das die exakte Anzahl der Plätze und den Status bündelt (z.B. "3 Plätze - Anfragen möglich"). Nach einem Team-Plenum kam jedoch die Frage auf, ob die Erfassung exakter Kapazitäten für den MVP-Status der Anwendung wirklich notwendig ist oder den Onboarding-Prozess für Professoren unnötig verkompliziert.

## Decision

Es wurde entschieden, den Betreuungsstatus auf eine **simple, binäre Checkbox ("Anfragen erhalten?")** zu reduzieren. 

Auf die exakte Zählung und Verwaltung von konkreten Betreuungsplätzen (Zahlenwerten) wird im MVP bewusst verzichtet. Diese Lösung reduziert die kognitive Last bei der Profilerstellung ("Frictionless UI") drastisch. Der Kernzweck der Plattform – das Verbinden von Studierenden und Professoren – wird durch diesen simplen An/Aus-Schalter vollkommen erfüllt.

Die Entscheidung beweist, dass agile Entwicklung und User Experience Vorrang vor bereits geschriebenem (komplexerem) Code haben. Beschlossen und umgesetzt von Nikita Pasichnyk.

## Regarded Options

| Kriterium | Kombiniertes Dropdown (Status + Anzahl) | Simple Checkbox (Status An/Aus) |
| :--- | :--- | :--- |
| **Kognitive Last (UX)** | Höher (exakte Kapazitätsplanung nötig) | Sehr gering (simpler Toggle) |
| **Gefahr inkonsistenter Daten** | Gebannt (da kombiniert in einem Feld) | Gebannt (nur 0 oder 1 möglich) |
| **Wartungsaufwand Backend** | Backend muss Werte parsen und splitten | Direkte Boolean/Integer-Zuweisung |
| **Nutzen für MVP** | "Nice to have" | Absolut ausreichend |
