# 09: Wahrung der referenziellen Integrität (Foreign Keys)

## Meta

Status
: Work in progress - **Decided** - Obsolete

Updated
: 23-Jun-2026

## Problem Statement

HTML-Select-Felder (Dropdowns) geben bei Nicht-Auswahl oder Platzhalter-Optionen (wie "— keine —") oft Standardwerte wie den String `"0"` oder `""` zurück. 

Wenn diese Werte ungeprüft von Flask an SQLAlchemy übergeben werden, um einen Foreign Key (`facheinheit_id` oder `degree_program_id`) zu befüllen, führt dies zu einem Datenbankfehler (Integrity Error), da in der referenzierten Tabelle kein Datensatz mit der ID `0` existiert. 

## Decision

Es wurde serverseitig eine konsequente **Konvertierung von Frontend-Platzhalterwerten in SQL-konforme `NULL`-Werte** implementiert.

In der `app.py` wird die Eingabe validiert. Gibt ein Dropdown den Wert `0` zurück, wird dieser durch den Python-Wert `None` ersetzt (z.B. via `form.facheinheit_id.data or None`), was SQLAlchemy sicher als SQL-`NULL` in die Datenbank schreibt. 

Dies stellt sicher, dass die referenzielle Integrität der relationalen Datenbank nie verletzt wird und Profile ohne zugeordnete Fachbereiche sauber existieren können.

## Regarded Options

* **Option A: Blindes Speichern des Default-Wertes (`0`).** Führt unweigerlich zu Foreign-Key-Fehlern in der Datenbank und potenziellen App-Abstürzen (HTTP 500).
* **Option B: Backend-Konvertierung zu `NULL` (Gewählt).** Sichert die referenzielle Integrität, fängt fehlerhafte Client-Requests sicher ab und macht den Code robust gegenüber unvollständigen Profilen.
